基于当前已完成的实现，更新与其实际行为相关的文档。额外上下文：${@:-无；请从当前工作区变更推断。}

先执行以下核查，不要仅凭提交信息或推测修改文档：
1. 检查 `git status --short`、相关 diff 与现有文档，保留所有用户未提交的工作。
2. 找出实现变更实际影响的文档：
   - `docs/superpowers/specs/` 中对应的 design spec；
   - `ARCHITECTURE.md`；
   - `AGENTS.md`；
   - `README.md` 与 `README.zh.md`。
3. 逐项将文档描述与当前代码、配置、测试和运行流程核对；只更新确实受影响的文件。没有证据表明需要更新时，不要为了完整性而改动。
4. 对每个需要更新的文件，保持既有语言、结构、术语和 Markdown 风格；同步中英文 README 的等价信息。
5. 不修改历史设计决策来掩盖实现偏差。若实现与 design spec 冲突，明确报告冲突，并在有证据时更新 spec 的“实现偏差”或等价章节。
6. 核对文档链接、路径、命令和版本号；不要新增未经验证的命令或承诺。

完成后：
- 列出每个修改的文件及其与实现对应的原因；
- 明确列出已检查但无需更新的目标文档；
- 报告运行的文档相关验证（若无适用验证，也应说明）。
